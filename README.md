# lanclip

Общий буфер обмена между Mac и Windows-ПК Павла по локальной сети. Скопировал
на одной машине — на другой нажал глобальный **Ctrl+Shift+V** — содержимое
приехало и (если `autoPaste: true`, по умолчанию так) сразу вставилось.
Текст, картинки, файлы и папки — байт-в-байт.

Топология, устройство протокола и полный список реализованного —
`ai/PROJECT.md`, `ai/FEATURES.md`, `proto/PROTOCOL.md`. Накопленные грабли —
`ai/ERRORS.md`. Этот файл — только то, что нужно, чтобы поставить,
подружить обе машины и проверить, что всё живо.

## Установка на Mac

```bash
./scripts/install-mac.sh
```

Идемпотентно, безопасно перезапускать. Ставит бинарник в
`~/.local/bin/lanclipd`, конфиг в `~/.config/lanclip/config.json` (создаётся
один раз, с новым токеном и пустым `peers`, если файла ещё не было), лог в
`~/Library/Logs/lanclip.log`, LaunchAgent `space.paulislava.lanclip`.

**Разрешения — выдаются только руками, программно получить нельзя:**

1. **Accessibility** (без него Ctrl+Shift+V наполняет буфер, но не
   вставляет — синтез молча не работает, диалог сам не появляется):
   Системные настройки → Конфиденциальность и безопасность → Accessibility
   → «+» → Cmd+Shift+G в диалоге выбора файла → вписать точный путь
   `~/.local/bin/lanclipd` → включить тумблер.
2. **Local Network** (без него агент не видит соседа по LAN). На macOS 15+
   диалог запроса разрешения фоновому LaunchAgent может не показаться вовсе
   — первый запуск обязательно делается руками из Терминала:
   ```bash
   launchctl bootout gui/$(id -u)/space.paulislava.lanclip
   ~/.local/bin/lanclipd serve --config ~/.config/lanclip/config.json
   ```
   Дождаться диалога, разрешить, остановить (Ctrl+C), вернуть LaunchAgent:
   ```bash
   launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/space.paulislava.lanclip.plist
   ```
   Разрешение привязано к пути и подписи бинарника, а не к способу
   запуска — дальше LaunchAgent работает с уже выданным доступом.

Подробнее и с обоснованием — `docs/mac-setup.md`.

## Установка на ПК

Требует прав администратора на ПК (нужны `netsh http add urlacl` и
`New-NetFirewallRule`). Код доставляется с Mac по SSH, установка выполняется
на самом ПК:

```bash
# с Mac — собрать и залить код на ПК (использует csc.exe на ПК, без NuGet/SDK)
./scripts/sync-win.sh
```

```powershell
# на ПК, из PowerShell с правами администратора
& C:\Users\PaulIsLava\lanclip\scripts\install-win.ps1
```

Идемпотентно. Ставит бинарник в `%USERPROFILE%\.local\bin\lanclipd.exe`,
конфиг в `%USERPROFILE%\.config\lanclip\config.json` (создаётся один раз,
не трогается при повторных запусках), резервацию `netsh http add urlacl`
для `http://+:8901/`, правило файрвола на входящий TCP 8901 и задачу
планировщика `lanclip` с автозапуском при входе пользователя в систему
(`-AtLogOn`, интерактивная сессия — резидентному агенту нужен настоящий
системный буфер обмена, который существует только там). Отдельных
разрешений на Windows выдавать не нужно — синтез Ctrl+V не требует допуска.

## Обмен токеном

Обе машины узнают друг друга по общему токену в поле `token` конфига — он
генерируется автоматически при установке (по 128 случайных бит на каждой
стороне независимо), но **разный** на Mac и на ПК, пока не выровнен вручную.
После установки на обеих машинах:

1. Скопировать значение `token` из конфига одной машины в конфиг другой
   (значения должны совпасть буквально).
2. Дописать адрес другой машины в `peers` каждого конфига (несколько
   вариантов через запятую не помешают — резолвер перебирает их по
   порядку):
   - на Mac: `"peers": ["pc", "192.168.1.184"]`
   - на ПК: `"peers": ["cab-wsm-0667615.local", "192.168.1.102"]`
3. Перезапустить оба агента:
   ```bash
   launchctl kickstart -k gui/$(id -u)/space.paulislava.lanclip
   ```
   ```powershell
   Stop-ScheduledTask -TaskName lanclip
   Start-ScheduledTask -TaskName lanclip
   ```

**Порт — 8901 на обеих машинах**, не 8899 (8899 занят на Mac посторонним
процессом `server.py`). `config.port` служит и своим сервером, и портом
соседа — если сменить порт на одной машине и не сменить на другой, связь
молча отвалится.

## Как проверить, что всё живо

```bash
# Mac
launchctl print gui/$(id -u)/space.paulislava.lanclip   # ожидаем state = running
~/.local/bin/lanclipd status                            # порт, буфер, сосед
tail -n 50 ~/Library/Logs/lanclip.log
```
```powershell
# ПК
Get-ScheduledTask lanclip
Get-Process lanclipd
```

Полная кросс-машинная проверка (health в обе стороны + `get` манифеста с
обеих машин):
```bash
./scripts/smoke.sh
```

**Про прокси на Mac:** в окружении обычно выставлен `HTTP_PROXY` на
корпоративный прокси, а локальная подсеть не входит в `NO_PROXY`. Любой
`curl` к соседу без обхода прокси получит `503` от самого прокси, а не
ответ агента:
```bash
curl -s -m 5 -o /dev/null -w "http_code=%{http_code}\n" http://pc:8901/health
# → http_code=503 (это прокси, не сосед)

curl -s -m 5 --noproxy '*' -H "x-clip-token: <ваш токен>" http://pc:8901/health
# → {"ok":true,"host":"DESKTOP-NGNE28E","version":1} — реальный ответ агента
```
Сами агенты (`lanclipd`/`lanclipd.exe`) через прокси не ходят — это касается
только ручной/скриптовой диагностики с Mac-терминала. `scripts/smoke.sh` уже
учитывает это и везде вызывает `curl --noproxy '*'`.

Разово забрать буфер соседа из терминала, минуя хоткей:
```bash
~/.local/bin/lanclipd get --config ~/.config/lanclip/config.json   # только манифест, JSON
~/.local/bin/lanclipd pull --config ~/.config/lanclip/config.json  # забрать и вставить в свой буфер
```

## Как проверить хоткей Ctrl+Shift+V вручную

**Это должен сделать Павел лично, физическим нажатием.** Хоткей ни разу не
проверялся синтетически намеренно: при попытках подготовить безопасную
проверку синтез уже дважды уходил не в то окно (см. `ai/ERRORS.md`), после
чего это было прямо запрещено — не синтезировать нажатия и не эмулировать
хоткей ни на одной из машин.

1. Скопировать что-нибудь на компьютере-источнике обычным Cmd+C / Ctrl+C.
2. На компьютере-приёмнике нажать **Ctrl+Shift+V** (сочетание одно и то же
   на Mac и Windows).
3. Если `autoPaste: true` (по умолчанию так) — содержимое сразу вставится в
   поле под курсором, как обычный Ctrl+V. Если поля ввода нет — окажется в
   буфере обмена, вставить Ctrl+V вручную.
4. Признак успеха: на экране появляется скопированное с другой машины
   содержимое. Признак проблемы: ничего не произошло — проверить
   всплывающее уведомление (Notification Center на Mac, трей на Windows),
   агент сообщает туда причину отказа (сосед не найден, токен неверный и
   т.п.).
5. Для файлов: после вставки на Mac полезно открыть Finder — уведомление
   заранее покажет число файлов и суммарный размер в мегабайтах.

Если хоткей совсем не реагирует на Mac — почти всегда дело в разрешении
Accessibility (см. «Установка на Mac» выше). На ПК разрешений выдавать не
нужно.

## Известные ограничения

Ни одно из перечисленного не является багом в смысле «забыли починить» —
все проверены и задокументированы (подробности и цифры — `ai/ERRORS.md`,
`ai/FEATURES.md`):

1. **Прокси на Mac** уводит диагностический `curl` к соседу через
   корпоративный прокси и получает `503` от него — см. раздел про проверку
   выше, всегда добавлять `--noproxy '*'`.
2. **SSH-сессия на ПК** живёт в `SessionId=0` с изолированным пустым
   буфером обмена; агент и рабочий стол — в `SessionId=1`. Буфер ПК по SSH
   не увидеть в принципе — проверять только через сам агент (`status`,
   `get`, уведомления).
3. **Один порт на обе роли.** `config.port` — это и порт своего сервера, и
   порт, на котором агент ищет соседа. Смена порта на одной машине без
   такой же смены на другой молча рвёт связь.
4. **Симлинки на каталоги внутри скопированной папки** молча пропускаются
   при обходе — манифест окажется неполным, без единого предупреждения.
5. **Автоподъём задачи планировщика после падения процесса** (`RestartCount`/
   `RestartInterval` на ПК) не подтверждён экспериментом — в проверке не
   поднял задачу за две минуты. Автозапуск при входе в систему — работает и
   подтверждён.
6. **Триггер `-AtLogOn`** проверен только структурно, не настоящим циклом
   выхода и входа в систему. Если после перезагрузки ПК агента нет —
   смотреть сюда первым делом.
7. **Число попыток `pull` нигде не видно пользователю.** При
   `changedMidTransfer` (буфер соседа уехал посреди передачи) делается один
   автоматический повтор — «успех с первой попытки» неотличим от «успех со
   второй».
8. **Причина гонки `409 changedMidTransfer` на Windows не установлена**
   (наблюдалась ~20% на одном нагруженном сценарии). Автоповтор её гасит
   для пользователя, но не объясняет первопричину.
9. **Легаси-тип буфера `NSFilenamesPboardType` на Mac** оставлен для старых
   приложений, но его нельзя проверить удалением строки — macOS синтезирует
   этот тип сама поверх современного, так что тест ничего бы не показал.
10. **Лимит длины пути — 150 байт UTF-8 на компонент, 400 байт UTF-8 на весь
    путь**, считается в байтах, не в символах. Очень длинные неанглийские
    (кириллица, иероглифы, эмодзи) имена файлов будут отвергнуты там, где
    английские с тем же числом символов прошли бы.

## Структура репозитория

- `mac/` — Swift Package: `LanClipCore` (протокол, конфиг, стейджинг,
  pull-клиент) и исполняемый `lanclipd` (CLI, хоткей, уведомления).
- `win/` — C# 5.0 / .NET Framework 4.8, собирается `csc.exe` без Roslyn и
  без NuGet/SDK (`win/build.ps1`).
- `proto/PROTOCOL.md` — формат HTTP-протокола между агентами.
- `scripts/` — установка (`install-mac.sh`, `install-win.ps1`), доставка
  кода на ПК (`sync-win.sh`), генерация токена (`gen-token.sh`),
  кросс-машинная проверка (`smoke.sh`).
- `ai/PROJECT.md`, `ai/FEATURES.md`, `ai/ERRORS.md`, `ai/features/` —
  проектная документация для того, кто будет чинить это через полгода.
